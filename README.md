# YuriQuant

**A 股全市场量化研究与生产系统。**

从原始行情到每日可执行榜单，覆盖数据采集、因子研究、模型训练、组合构建、回测、
风险归因、生产调度与报告交付的完整链路，单机可跑通全流程。

系统的设计围绕三条原则：**回测不使用未来信息、研究结论可样本外复现、策略可直接投产**。
研究代码与生产代码共用同一套数据层、因子层与回测引擎——任何一个在报告里出现的策略，
都可以用同一份代码在每日生产里跑出来。

## 一、核心策略

### 1.1 yqcore 定版策略

同一信号族的三档配置，差异在持仓集中度与执行层。回测窗口 2019-01 至 2026-09，
初始资金 100 万元。

| 档位 | 形态 | 持仓 | 年化 | Sharpe | 最大回撤 | 年换手 |
|---|---|---|---|---|---|---|
| **宽基档** `breadth` | 全因子正交面板 + 月频 Top10% 等权，带缓冲带 | 均 614 只 | **21.81%** | 1.013 | 26.6% | 17.1% |
| **集中档** `focus-k15` | 四周期融合信号 + TopK15，带缓冲带 | 15 只 | **29.60%** | 1.113 | 38.2% | 87.6% |
| **小资金档** `focus-k8` | 同上 + 每行业 ≤1 只 | 均 5.9 只 | **36.58%** | 1.271 | 36.3% | 92.4% |

`focus-k8` 在 8 个完整年度中全部为正，最差年度 +8.69%（2022）。

三档并非「收益越高越推荐」：集中档的高收益来自持仓集中度，代价是接近 40% 的回撤与
小资金下的整手摩擦。**选择依据是资金规模与风险承受度，而非历史收益排序。**

### 1.2 ETF 轮动

跨资产 ETF 池 50 只（宽基 / 行业 / 主题 / 债券 / 商品 / 跨境），两套方案按风险偏好分开运行：
口径为「调仓日收盘后出信号、次日开盘成交」（T+1 open），正常资金无白名单：

| 方案 | 形态 | 年化 | Sharpe | 最大回撤 |
|---|---|---|---|---|
| **monthly**（默认） | 月频 Top5 + 逆波动（σ 下限 10%）+ 12% 波动目标 + 债金防御腿 | 10.65% | 0.94 | 15.97% |
| **balanced** | Top5 · 周频 · ERC 等风险贡献 | 13.33% | 0.64 | 29.89% |

上表为**调仓相位均值**（monthly 月内五相位 13.08 / 11.68 / 10.17 / 9.11 / 9.23，
极差 3.97pp；balanced 周内五相位 13.27 / 11.01 / 13.98 / 16.07 / 12.32，极差 5.06pp）。
单相位最好值分别可达 13.08%（monthly）与 16.07%（balanced），但都含相位红利，
不能按最好相位做预期。两档调仓节奏不同（月频 / 周频），**按两个独立账户分别运行**；
「60% monthly + 40% balanced」的合并方案经测试后判否（两腿调仓日不同步，合并等价于
两个账户，报告 §14.10）。

> **2026-11-19 两次口径修正**：① 池子由比赛期 45 只恢复为 50 只全量，方案改英文
> 功能名，删除「不少于 5 只」合规补位档；② **原 `core`（Top3 集中档）退役** ——
> 其 k=1 单相位 24.24%/0.89 看似最高，但五相位均值仅 14.27%/0.52/MDD 39.2%
> （最差相位 46.7%、Calmar 0.36），被 `monthly`（Calmar 0.67）支配，且相位极差
> 14.06pp 远大于 balanced 的 5.14pp。比赛期 45 只数字（core 30.63%/1.16）只作历史
> 复现，不可与本表混引。

收益来源已做分解：选标与集中放大是两件事，前者贡献主要超额，后者的效果取决于池内
右尾厚度而非普遍规律；而集中度带来的**执行相位依赖**在正常资金口径下是负资产
（core 的教训），故默认档选月频。

### 1.3 因子看板

888 个因子 × 4 组期限的分层业绩，每个因子真跑两端分位组合，13 类逻辑族筛选，
输出单文件 HTML（零后端、可离线打开）。

看板定位是**横向比较工具**，用于观察因子在全市场上的相对强弱，与上述策略业绩不可并列。

### 1.4 策略总览页

`reports/strategies/index.html` 是统一前端入口：按 `横截面策略 / 事件驱动策略 / ETF 策略`
分组列出 6 张卡片（股票线 K8 / K15 / 广度、事件驱动、ETF 两档），卡片指标统一为
**年化 / Sharpe / MDD**，点击进入该策略的**历史回测**详情页（净值 / 回撤 / 分年度）。
**模拟持仓是独立入口**：`reports/strategies/live.html`
只列已开立纸面账户的策略（当前仅 K8），点开看持仓与持仓期表现。ETF 详情页曲线为
单相位 k=1，与 §1.2 的五相位均值不可混引；事件驱动详情页（`inc_pure.html`）的数字
由策略层 `strategy/event_driven.py` 现算，与 `scripts/live/inc_pure_live.py` 共用同一套
事件定义。卡片由 `strategy/catalog.py` 的 `CATALOG` 生成（策略登记表：key / 入口 /
报告目录，只登记不搬实现）；策略参数真源仍是 `etf_contest_spec.PROFILES`、
`strategy/registry.TIERS` 与 `strategy/event_driven.py`。

## 二、系统能力

### 数据层

- **数据源可插拔**：商业 SDK / CSV / Mock 三态切换，只改配置不动业务代码
- **本地 Parquet 增量缓存**：15+ 类表（行情 / 分钟 / 财务三表 / 行业 / 股本 / 股东 /
  涨跌停停牌 / 指数成分），带增量水位与数据指纹
- **Point-in-time 纪律**：股票池取指数成分的历史快照，财务三表按公告日展开为日频面板，
  行业归属与自由流通市值同样按公告日构造
- **可交易性掩码**：停牌、涨停封板、跌停封板、ST 显式建模，回测中不存在「买到买不到的票」
- **分钟数据内存映射**：GB 级分钟行情按年分区 `np.memmap` 稠密化 `[日, bar, 股票]`，
  之上直接计算 95 个分钟→日频统计特征与时段切片特征
- **另类数据自建通道**：巨潮快讯（2014 年起自建存档 119 万条）、增减持 26.6 万行、
  宏观日历 6.5 万行、董监高与实控人变动

### 因子层

- **因子库**：**888 个登记因子 × 5565 只股票（含退市回补）× 2016–2026**，
  `registry` / `panels` / `evals` 三件套，血缘与公式全程可溯
- **多因子谱系**：50+ 算子注册表、通达信口径指标 57 个、Alpha101/158/191/360、
  券商特征族 36 个、论文复现 21 式
- **五种挖掘引擎**：穷举、遗传规划、GFlowNet、AlphaPool 强化学习、LLM-MCTS
- **合成七法**：IC 加权、PCA、IC_IR 最大、半衰加权、等权、正交、ML Stacking
- **预处理**：去极值 → 行业 + 市值中性化 → 标准化，向量化实现 2.96 倍提速且与
  逐日实现逐位一致

### 模型层

- **预测器**：Ridge / LightGBM / TabICL，滚动时序交叉验证；表格基础模型三级对照显示
  中小池 TabICL 最优、全 A 大截面 GBDT 不可替代
- **标签工程**：多 horizon × 多变换 × 超额口径 × 隔夜窗口，embargo = horizon 防泄漏
- **模型即因子**：预测面板回写因子库，模型与因子血缘双向溯源

### 组合与风控层

- **组合优化**：QP 五法（min_var / tev / mvo / risk_parity / Black-Litterman）+ HRP，
  约束覆盖预算、上下限、行业中性、基准偏离、逐股变动上限
- **风险归因**：α/β 分解（Newey-West t）、Brinson（Carino 链接）、Euler 风险分解 +
  VaR/CVaR 成分
- **执行层**：日 / 周 / 月调仓，整手约束，逐股冲击成本 `η·σ·√(Q/ADV)`
- **容量表**：集中度 × AUM 二维实测，回答「这个策略能装多少钱」而非只报百分比

### 回测引擎

- 向量化实现，交易成本、涨跌停与停牌过滤、T+1 开盘可执行口径为全链默认
- 反过拟合三件套：CSCV PBO（12870 个组合秒级）、Deflated Sharpe Ratio、
  三段式 train / valid / test + 配置冻结

### 生产与交付

- **每日盘后自动推理**：增量更新数据 → 尾部重算 → 重训 → 全 A 排名与可交易候选，
  单条命令一次配齐协同参数
- **面板月度重建**：守卫式重建，避开收盘后的出榜窗口
- **生产 IC 台账**：按日推进的 IC / 中性化 IC / 风格暴露序列，历史段与每日增量共用
  同一段指标代码，可直接拼成一条不含断点的序列
- **交付物**：自包含 HTML 看板（A 股红涨绿跌）、XLSX、邮件日报

## 三、架构

```
data/        数据层 —— 数据源抽象、增量缓存、PIT、可交易掩码、分钟面板、另类数据
factor/      因子层 —— 算子库、挖掘引擎、合成、预处理
model/       模型层 —— 特征漏斗、标签、预测器、训练评价、注册表
strategy/    策略层 —— 因子值 → 组合权重
optimize/    优化层 —— QP / HRP / BL、成本建模、风险归因、多期执行
backtest/    回测层 —— 向量化引擎、成本模型、绩效指标
research/    研究层 —— IC 与分层、归因、DPP 选样、因子库、报告渲染；
             **判据真源**（`factor_criteria` 准入 / `factor_library.MATURITY_GATES`
             晋升 / `dup_criteria` 重复性），脚本只准调用、不准另写一份
stats/       统计层 —— 稳健统计、PBO / DSR、显著性检验
monitoring/  监控层 —— IC 台账、告警、账本、拥挤度
scripts/     入口层 —— 119 个可执行入口（ingest / builders / pipelines / factors /
             portfolio / evaluation / reporting / textmining / live / common）
config/      参数真源 —— settings.yaml（环境与数据源）/ baselines.yaml（基线登记表）/
             schedule.yaml（调度登记表）
tests/       125 个测试文件 / 1767 个用例
reports/     实验结果与交付物（本地证据库，不进版本库）
```

依赖方向单向：`scripts → strategy/optimize/model/factor/data`，`tests` 同时覆盖库层与
生产链脚本。研究代码与生产代码共享同一份数据层与回测引擎，不存在「报告一套代码、
上线另一套代码」的分叉。

## 四、快速开始

```bash
git clone https://github.com/Yuri-Mizuki/YuriQuant.git
cd YuriQuant
pip install -e ".[dev]"

pytest -q                      # 1767 个用例，无需数据凭证
```

**没有商业数据源也能跑通全链**：把 `config/settings.yaml` 的 `datasource.type` 切成 `csv`，
或给任意管线加 `--mock`，全部在合成数据上执行。

接入真实数据后：

```bash
python -m scripts.ingest.update_data                          # 增量更新 Parquet 缓存
python -m scripts.pipelines.rolling_grid_alla                 # 全 A 多年度 walk-forward
python -m scripts.live.yqcore rank --preset dingban           # 每日出榜
python -m scripts.reporting.yqcore_dashboard --open           # 定版看板
python -m scripts.reporting.factor_board                      # 因子看板
python -m scripts.reporting.strategy_home                     # 策略首页（回测详情）+ 模拟持仓页
python -m scripts.evaluation.caliber --signal <key>           # 单策略回测
```

> **数据源说明**：主数据源 AmazingData 为商业分发的 SDK（非公开，需自行获取授权）。
> 这不影响复用全部架构与算法代码——数据层抽象允许任何数据源（包括自有 CSV）接入同一条管线。
